# Full local QA — DaBin 0.4.28 (83), 4 October 2026

Search now accepts typing and native paste after opening, clearing, and reopening the board. Focus is restored after the animated host transition. Command-V and Edit → Paste recover the query editor when a non-editing Search control owns focus; an already-active text editor retains its normal selection-aware paste. Search paste never creates a capture.

Live QA exposed a shortcut collision: Control–Option–Space selected the next macOS input source. Adding Shift still switched the language in the live check despite an exact reservation lookup reporting it free, so the final Search key is **K**, using **Control–Option–K** by default. **Command–K** inside DaBin remains unchanged; default clipboard capture remains **Control–Option–V**. Saved modifier choices are preserved. Enabled macOS shortcut reservations are checked before registering K or V; conflicts and failed reads report the existing Settings error. The unsuccessful Space alternatives are retained in the evidence.

## Repairs found by QA

The Search regressions exposed focus timing and responder-chain paste gaps, now fixed in production. Older scope/resize fixtures were updated to assert the new global, stable-height date-column search behavior. The default render fixture now explicitly enables optional neighboring context when testing it. Version checks validate the current shared Info.plist and generated Xcode configurations instead of pinning an obsolete release. Privacy checks now assert current recoverable/permanent deletion wording, and Xcode smoke fixtures release their Core Data stores before deleting temporary database files.

The Search GUI launcher previously stalled while loading a test library from Documents. It now embeds the library inside its temporary signed fixture bundle, writes to a temporary evidence directory, requires its completion sentinel, and terminates only its own exact process after a timeout. The privacy and island render scripts now include their complete source dependencies. Original unsuccessful runs and subsequent repairs are retained rather than relabeled as passes.

Keyboard Navigation is disabled on this Mac. The Search test checks valid retained popup focus under that setting, and still verifies Escape dismissal and Return activating Done. It checks traversal when the system enables it; system preferences were not changed.

## Limits and diagnostics

This is local ARM64 verification on the macOS/SDK versions recorded by the reports, not signed distribution or macOS 14 runtime approval. The full run detected one connected display; multi-display geometry fixtures pass, and earlier monitor-specific evidence remains separately recorded. Physical OS-level global-hotkey dispatch remains a manual check: the per-application CUA key injection did not navigate from Settings, although registration, reserved-key checks, labels and the native callback/navigation regressions pass. Command–K is verified live. Completion of a real drag into arbitrary external applications remains unverified by the automation; native drag payloads and source preservation pass. Receiving applications ultimately choose which representations they accept.

A non-fatal AppKit NSTableView reentrancy warning remains during forced SwiftUI test layout. The prior captured stack and current audit indicate AppKit row-height recalculation; this work does not claim the warning is eliminated. Privacy/render fixtures and all stress data are synthetic. No personal capture was edited, no public binary was released, and no Store submission was made.
